源码来自用户上传的 `bids.zip`。9 个应用文件按原始字节导入：`server.py`、`discovery.py`、`deploy_remote.py`、应用 `.gitignore`，以及 `static/` 下 HTML、JS、CSS、SVG 和 WebP 文件。各文件 SHA-256 见 [source-manifest.json](source-manifest.json)。业务实现未改写。

原 README 含具体管理员身份，已改写为通用运行说明。测试、仓库说明和流程文档属于本仓库新增内容。

以下内容未导入：真实 `seed.json`、历史验收记录和截图、Python 字节码、macOS 元数据。此前上传的 SSH 私钥与原始对话也不在仓库中。未访问服务器、未更改生产数据、未执行部署脚本。

## 当前验证结果

在 Python 3.12 和 Node.js 24 下：

- 17 项 Python 测试通过：数据校验、SQLite 项目持久化、版本冲突、置顶/弃标/恢复、附件处理、真实 HTTP 健康/静态资源/未登录访问限制，以及固定样本的公告列表与 RSS 解析。
- 5 项 Node 测试通过：北京时间日期边界、领件与递交状态、有效/历史节点、终态和弃标分类，加载的是原 `app.js`。
- `server.py init` 重复执行成功；`backup` 生成的 SQLite 快照通过完整性检查。
- JavaScript 语法检查通过；来源文件哈希保持一致。

HTTP 测试在临时数据目录中直接启动原 `Handler`，未替换认证模块；这些测试不等于完整 `serve` 和登录流程验收。

## 尚未验证的能力

完整登录依赖原官网 `workflow` 模块及 `console_sessions` 账号库初始化逻辑，压缩包未包含。使用不存在的独立测试账号库运行 `serve` 时，已确认启动会因无法打开账号库而失败。需要提供认证模块及建库/迁移代码，生产账号数据库不应提交到 Git。

本次实际调用公告检索，选择中国政府采购网 4 个栏目，均返回网络访问失败，未得到候选。随后 HTTPS 探测在代理 CONNECT 阶段返回 403；这不是采购站点“没有项目”的证据。尚未证明当前云环境能成功抓取线上公告；需放通所需外网域名后重新验证。其他公告来源未做在线验证。

原服务器专用 `deploy_remote.py` 没有执行，生产登录、部署、备份定时器及线上端到端行为均未验证。
